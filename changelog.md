# Changelog

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) · versions: [SemVer](https://semver.org/). Current version in [VERSION](./VERSION); installed version in `.ai-harness/.kit-version`.

## [1.1.0]

### Added

- Mandatory rules with a single owner in `Knowledge/standards.md` / `Governance/`: code preservation (attributes/annotations, logic, behavior), structure mirroring the existing feature, lean orchestrators (private handler helpers → feature services), rich domain **always**, business-rule changes only with human confirmation, full code documentation + `docs/` delivery.
- Unit tests in every change and **≥ 80% line coverage on every testable artifact** (a floor that can only be raised).
- Security baseline **S1–S12** and logging verification **L1–L8** on every implementation, with evidence tables in the run log.
- Execution bias within the permission matrix and final validation of every rule before DONE (`Runtime/loop.md`).
- Composable stack packs in `Knowledge/stacks/`: dotnet, blazor, java, android, typescript, node, angular, react, react-native, vue, flutter, ios, python, go, rust, php, ruby, database, data, devops, aws, azure, gcp, oci — detected by `fill-harness.py` and listed in `Agents/project.md`.
- Tools for the new stacks (`go.*`, `rust.*`, `php.*`, `ruby.*`, `android.*`, `ios.*`, `data.*`) and database migrations (`db.*`: local `auto`, shared `ask`, production `deny`); mobile releases `deny` for agents.
- `infra` workflow and `Tools/infra.md` (IaC plan `auto` in dev, apply `ask`, destroy `deny`; cloud CLI read-only; no long-lived credentials).
- `check-harness.py` language coverage: C#/Razor, Java/Kotlin, TypeScript/JavaScript/Vue, Python, Dart, Go, Rust, PHP, Ruby, Swift, Terraform/Bicep/YAML/JSON, Android/iOS manifests and SQL migrations.
- `Tools/bin/check-harness.py` (`harness.check`, `harness.coverage`): structure checks; on the diff, removed attributes and IaC protections, cloud secrets, sensitive files, insecure patterns, logging problems, untested code, test location and naming; coverage gate for Cobertura, JaCoCo and LCOV; `--install-hook` for a git pre-commit hook.
- `scripts/build-adapters.py`: every adapter generated from `adapters/source/harness.md` (`--check` in the self-tests).
- `tests/run.sh`: kit self-tests (install per stack, adapters, update/migration, check-harness rules, coverage, hook).
- `evals/`: rule-adherence scenarios and scorecard for any agent or model.

### Changed

- **One language: English** for the whole kit (content, headings, scripts and generated output). The scripts still read Portuguese READMEs of target projects.
- All kit and harness `.md` file names are lower-case. Adapters are still installed under the names each tool expects (`AGENTS.md`, `CLAUDE.md`, `CONVENTIONS.md`, …).
- Default adapter: `agents-md` (open convention) instead of `cursor`. Adapters never overwrite a project file that is not a harness file.
- Core template no longer names specific AI tools; Cursor-only extra rules (`opensource-first.mdc`, `rich-domain.mdc`) removed — their content is in the harness.
- Generated ADR file name is lower-case (`adr-0001-baseline-architecture.md`).

### Migration (1.0 → 1.1)

- Run `init-harness.sh <project> --update`: legacy upper-case names are renamed to lower-case (runs in progress included); conflicting copies become `<name>.legacy` for review.
- Knowledge files you filled in are preserved as they are (in Portuguese, if that is how they were written). Re-running `fill-harness.py` / `enrich-harness.py` replaces the old Portuguese generated sections with the English ones.
- Delete the stack packs your project does not use from `.ai-harness/Knowledge/stacks/`; later updates only refresh the ones you keep.
- Projects with the Cursor adapter may delete `.cursor/rules/opensource-first.mdc` and `.cursor/rules/rich-domain.mdc`.
- Rename `.ai-harness/Knowledge/ADR/ADR-0001-baseline-architecture.md` to lower-case if it was generated by an older kit (the update does this for `.md` files automatically).
